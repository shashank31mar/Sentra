## LOCKED DECISIONS (founder-ratified — the LLD states these as decided, does not re-open)

### D1 — Crypto ship = Option A: `[local-floor]` extra, pure-python `ecdsa` verify-only
- Base SDK stays `dependencies = []` (stdlib-only). Floor OFF in base = every call routes to hosted `/v1/validate` (the existing `local_floor_enabled=off` fail-secure path).
- `pip install aegion-guard[local-floor]` pulls **pure-python `ecdsa` (>=0.19.2)** (only `six` dep, `py2.py3-none-any` wheel) -> floor ON. Lazy-imported inside `local_floor`/verify module, never at package top, so a base install never imports it.
- **Vendor-unchanged holds for the niche too**: pure-python `ecdsa` vendors into a Lambda/Azure zip BY COPY (`.py` + `six`), unlike native `cryptography`.
- **Missing extra fails SECURE**: no verify lib present -> floor stays OFF -> hosted path. A "forgot the extra" mistake never fails open.
- **Side-channel caveat recorded-accepted**: `python-ecdsa`'s "not constant-time / not for production" caveat is about leaking a SECRET key via side-channel. We hold NO secret on the edge (verify-only; public key pinned). Caveat is therefore not applicable to our use; recorded as a documented risk-acceptance.
- **Signature verify is NON-NEGOTIABLE** for the floor: the whole value is "trust an in-process ALLOW without a round-trip", and that trust IS the signature check. Hash-only-over-TLS is a fail-open behind a CDN (ADR-029 Appendix D). Pure-stdlib ES256 is off the table (no stdlib elliptic-curve; hand-rolled secp256r1 = accept-forged-sig risk).
- **Cross-language note (state in LLD so the format isn't seen as Python-bent)**: the sign/verify contract is ES256-JWT + per-file SHA-256, language-neutral. Python is the WORST case (no stdlib EC). Go (`crypto/ecdsa`), Node (`crypto.verify`), Rust (`ring`), Java (JCA) all verify ES256 with stdlib/standard libs — no extra, no caveat. The packaging debate is Python-specific and does NOT shape the bundle wire format.

### D2 — Staleness knobs = 300s bound / 60s poll
- `MAX_STALENESS_BOUND = 300s` (5 min): a bad/revoked policy stops being trusted within 5 min.
- `REFRESH_CADENCE = 60s`: ~1 conditional-GET/min/agent, nearly all 304 Not-Modified.
- `dual_sign_overlap_window < MAX_STALENESS_BOUND` (config-validated at startup; violation = refuse to start).
- In-process bundle age computed from `time.monotonic()` (never wall clock — a wall rewind must not extend trust).
- **Cross-restart caveat**: `time.monotonic()` RESETS across a process restart, so it cannot measure an on-disk bundle's age after a cold start -> the **revocation epoch is the cross-restart freshness anchor** (a booted process reads the epoch and rejects any pre-epoch disk bundle).
- Accepted trade: a CDN/control-plane outage > 5 min -> fleet reverts to deny-by-default floor (fail-closed). Sized against HLD Appendix H availability target; the LLD reads Appendix H and confirms 300s is >= the target's recovery window or notes the residual.

### D3 — Cold-start bootstrap = persist last-good bundle + highest-seen version to disk
- SDK persists last-good bundle + `highest_seen_version` watermark to disk. A cold-started Lambda/Function bootstraps from disk with NO first-call WAN dependency -> the a1~45% local-resolve applies to the very first request (no cold-start escalation spike).
- **Verify-on-load exactly like a fresh fetch**: JWT sig + per-file SHA-256 + `bundle_version` vs persisted watermark + revocation-epoch check. A tampered disk bundle is rejected by the same gate (no new trust hole). A past-staleness-bound disk bundle on boot -> fail-closed (deny-by-default) until first successful poll.
- **Devil's-advocate resolved (why persistence does NOT make a bad bundle sticky)**: the fix for a bad bundle is ALWAYS server-side — emit a corrected bundle with a higher `bundle_version` (anti-rollback makes it win on the next poll <=60s, disk or memory alike) OR bump the revocation epoch (invalidates every pre-epoch bundle immediately -> edge reverts to deny-by-default until a corrected higher-version bundle arrives). Both are version/epoch-driven, NOT restart-driven. Restart is never the fix path; persistence does not slow the fix.

### D4 — Metering = DURABLE, NO-MISS (founder directive: "everything evaluated is metered and billed, period")
- **Overrides** the earlier best-effort/beacon answer. A locally-resolved LOCAL_ALLOW / LOCAL_DENY / DENY_BY_DEFAULT is an *evaluated event* and MUST be durably metered (NFR-12 >= 99.9%, and per founder, the target is lose-none).
- **Mechanism (no per-call WAN write — preserves the latency win)**:
  1. Every local verdict appends a compact meter record `{tenant_id, agent_id, request_id, decision, winning_source, ts}` to a **durable on-disk append-only journal** (fsync'd), OFF the hot path — the block/allow has already returned; append is ~microseconds.
  2. The background poll (already running, 60s) **flushes the journal in a batch** to a hosted meter-ingest endpoint, which performs WS-H's **idempotent `PutItem attribute_not_exists(request_id)`** into `sentra-meter-events`; only server-ACKed records are pruned from the journal.
  3. Crash before flush -> journal survives on disk -> replayed on next boot -> dedup makes replay a no-op. **At-least-once delivery + idempotent `request_id` dedup = effectively-once. Zero evaluated events lost.**
  4. ESCALATE-path calls reach the server anyway -> metered server-side on arrival (today's path). Uniform "meter everything" holds: server meters what it sees; edge journals what resolves locally.
- **Binds to WS-H**: `sentra-meter-events` durable-before-ack ledger, `request_id` dedup key, recomputed-SUM rollup (never `ADD +1`), DLQ-on-exhausted-retry. WS-A produces the durable edge journal + flush; WS-H owns the hosted ledger + aggregator.
- **CROSS-DOC RECONCILE FLAG (propagate-change target)**: `tasks/serverless-edition/ws-h-metering.md:71` currently says the edge beacon "carries only volume ... NOT covered by the no-miss guarantee (the emitting process may die before flush)." Per D4 the per-decision meter event IS no-miss (durable journal, not a lossy beacon); the beacon-loss carve-out survives ONLY for coarse volume-band telemetry, NOT the per-decision meter event. The LLD's Cross-references must name this so it reconciles when WS-H's LLD is authored.

## TENETS (carried from HLD 4 — verbatim intent)
1. Enforcement is local; the control plane is never on the action path. (WS-A is the literal embodiment.)
2. Fail secure, never fail open. (Stale/tampered/rolled-back/revoked/no-bundle/crypto-missing all deny or escalate; edge-ALLOW-where-server-DENY is THE bug the design exists to prevent.)
3. Deny-by-default, explainable. (Every local verdict names Source.SENTRA_POLICY; the trail stays honest.)
5. Latency scales with risk, not volume. (Cheap deterministic subset resolves in-process; only ML/deep or out-of-subset escalates.)
6. The data boundary is the customer's to set. (Local eval keeps values in the customer env; ESCALATE egresses only redacted content; the meter journal holds no raw content.)
8. Honest staging. (LLD states plainly: as-is the floor's Serverless value is benign in-subset reads + availability; money-movement pairs with in-VPC — no overclaim.)
- Tie-breaker A — Shape the contract once, additively. (Bundle schema bound-to, not re-cut; phase=request byte-identical.)
- Tie-breaker C — Refresh out-of-band; decide in-process. (LOAD-BEARING: background poll refreshes freshness; the validate decision is made locally from cached state, never on the hot path.)
